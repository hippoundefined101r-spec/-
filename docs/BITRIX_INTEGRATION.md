# Что нужно от Bitrix для загрузки каталога в Mini App

Документ для разработчика/администратора сайта kirgu.ru (Bitrix).
Цель — отдать каталог (товары, фото, цены, скидки) в Telegram Mini App.

## 1. Способ передачи данных (выбрать один)

| Вариант | Что нужно | Комментарий |
|---|---|---|
| **YML-фид (рекомендуем)** | Ссылка на выгрузку каталога в формате YML/XML (как для Яндекс.Маркета) | Проще всего. Мы импортируем фид в свою БД и синхронизируем по расписанию. Нагрузки на сайт почти нет |
| **REST Bitrix** | Вебхук вида `https://kirgu.ru/rest/1/<token>/` с правами на инфоблоки каталога | Данные тянем напрямую по API |
| **Прямой доступ к БД** | Доступ (read-only) к MySQL Bitrix | Самый «низкоуровневый», по согласованию |

Если есть готовый **YML для Яндекс.Маркета/Google** — этого, скорее всего, уже достаточно. Пришлите ссылку.

## 2. Поля по каждому товару (минимум)

- **ID** — уникальный идентификатор (артикул/ID элемента)
- **Название**
- **Категория** (раздел каталога) — id и название
- **Цена** (текущая, в рублях)
- **Старая цена** / размер скидки (если есть акция) — для зачёркнутой цены и бейджа «−%»
- **Наличие** (в наличии / под заказ / нет)
- **Бренд / производитель**
- **Фото** — прямые ссылки (1 главная + дополнительные). Желательно ≥ 600×600
- **Описание** (текст)
- **Характеристики** — пары «свойство: значение» (бренд, цвет, материал, размеры и т.д.)

Желательно дополнительно:
- **Привязка к «комнатам»** (гостиная, спальня, кухня…), если есть — для навигации по комнатам. Если нет — сопоставим по категориям.
- **Хит / Новинка / Распродажа** — флаги для стикеров.

## 3. Категории и «комнаты»

- Дерево разделов каталога (id, название, родитель) — чтобы построить меню как на сайте: Мебель / Техника / Товары для дома / Товары для детей и подкатегории.
- Если на сайте есть разбивка «по комнатам» — выгрузить и её (или правило соответствия категория → комната).

## 4. Акции / скидки

- Список акций для блока «Акции»: заголовок, подзаголовок, картинка, (опц.) ссылка/условие.
- Либо признак скидки прямо у товара (старая цена) — тогда отдельный список не обязателен.

## 5. Фото

- Прямые URL картинок (например, `https://kirgu.ru/upload/iblock/...`).
- Важно: чтобы картинки **отдавались по прямой ссылке без блокировки** (Mini App грузит их в браузере пользователя). Если стоит защита от хотлинка — добавить наш домен в исключения или отдавать через CDN.

## 6. Обновление данных

- Как часто меняются цены/остатки? (раз в день / в реальном времени)
- Для YML — нормально синхронизировать каждые 10–30 минут.

## 7. Доступы

- Ссылка на фид **или** REST-вебхук с токеном **или** доступ к БД.
- Тестовый пример (хотя бы 10–20 товаров) — по нему настроим маппинг полей.

---

### Что мы сделаем на своей стороне
- Реализуем `BitrixCatalogSource` (маппинг полей Bitrix → товар).
- Импорт/синхронизацию каталога, серверные поиск/фильтры/пагинацию (уже заложены в API).
- Переключим Mini App с демо-данных на реальный каталог.
- Поднимем backend на HTTPS.

Достаточно прислать **ссылку на YML-фид** (или пример выгрузки) — с этого и начнём.
