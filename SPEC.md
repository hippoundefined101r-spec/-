# КИРГУ — Telegram Mini App. Спецификация

Полноценный интернет-магазин сети **КИРГУ** (kirgu.ru) внутри Telegram:
мебель, техника, товары для дома и детей. Доставка по Дагестану и Чечне.

Документ фиксирует архитектуру и решения. Источник истины по задачам — этот файл.

## 1. Принятые решения

| Вопрос | Решение |
|---|---|
| Объём MVP | Полный магазин: каталог → товар → корзина → оформление заказа (без онлайн-оплаты) |
| Источник данных | Bitrix (kirgu.ru). Готового API нет → строим backend со **слоем-адаптером**, источник подменяем |
| Frontend | React 18 + TypeScript + Vite + Telegram Web App SDK |
| Backend | Node.js + TypeScript + **Fastify** (единый язык с фронтом) |
| Связка аккаунта | Telegram `requestContact` → верифицированный телефон → матч с профилем Bitrix (без SMS) |
| Визуальный стиль | Строго фирменный: зелёный `#0AA64B`, гротеск (Gilroy / Manrope), белый фон |
| Оплата | В MVP отсутствует. Заказ — заявка, менеджер перезванивает |
| Получение заказа | Курьерская доставка (Дагестан/Чечня) + самовывоз из магазина |
| Доп. фичи MVP | Поиск и фильтры, навигация «по комнатам», блок акций |
| Репозиторий | Текущий, ветка `claude/laughing-volta-70jmpp` |

## 2. Архитектура

```
┌─────────────────────────┐      HTTPS/JSON      ┌──────────────────────────┐
│   Telegram Mini App      │  ────────────────▶   │   Backend (Fastify)       │
│   React + Vite (web/)    │                      │   server/                 │
│   - каталог/комнаты/акции│  ◀────────────────   │   - REST API              │
│   - корзина/заказ        │                      │   - проверка initData     │
│   - связка контакта      │                      │   - CatalogSource (адаптер)│
└─────────────────────────┘                      └─────────┬─────────────────┘
                                                            │
                                          ┌─────────────────┴───────────────┐
                                          │  CatalogSource (интерфейс)        │
                                          │  ├─ MockCatalogSource (сейчас)    │
                                          │  └─ BitrixCatalogSource (позже)   │ ──▶ Bitrix (REST/фид/БД)

```

Ключевая идея — **`CatalogSource`**: интерфейс источника каталога. Сегодня работает
`MockCatalogSource` (демо-данные), завтра подключаем `BitrixCatalogSource` без изменений
в роутерах и фронте. Способ доступа к Bitrix (REST-вебхук / YML-фид / прямая БД)
выбирается позже — на контракт это не влияет.

## 3. Доменная модель

- **Category** — верхняя категория: Мебель, Техника, Товары для дома, Товары для детей.
- **Room** — «комната»: Гостиная, Спальня, Детская, Кухня, Прихожая, Дом и сад, Офис, Ванная.
- **Product** — товар: `categoryId`, `rooms[]`, бренд, цена/старая цена, наличие, фото, характеристики.
- **Stock** — акция/скидка (как блок на главной сайта).
- **Order** — заявка: позиции, контакт, способ получения (курьер/самовывоз), статус.
- **User** — Telegram-пользователь; после `requestContact` связывается с профилем Bitrix по телефону.

## 4. Контракт API (v1)

Базовый префикс `/api`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/catalog/categories` | Список верхних категорий |
| GET | `/catalog/rooms` | Список «комнат» |
| GET | `/catalog/products` | Товары. Параметры: `q`, `category`, `room`, `brand`, `minPrice`, `maxPrice`, `sort`, `inStock`, `limit`, `offset` |
| GET | `/catalog/products/:id` | Карточка товара (+похожие) |
| GET | `/catalog/brands` | Бренды (для фильтра) |
| GET | `/stocks` | Акции |
| POST | `/auth/telegram` | Проверка `initData`, выдача сессии пользователя |
| POST | `/auth/link-contact` | Связка телефона (из `requestContact`) с профилем Bitrix |
| POST | `/orders` | Создание заявки |
| GET | `/orders` | Заказы текущего пользователя |

Все защищённые запросы несут заголовок `Authorization: tma <initDataRaw>`;
сервер проверяет подпись по `BOT_TOKEN` (алгоритм Telegram WebApp).

## 5. Безопасность

- Проверка `initData` — HMAC-SHA256 по схеме Telegram (секрет = `HMAC("WebAppData", BOT_TOKEN)`),
  плюс контроль свежести `auth_date`.
- Телефон из `requestContact` Telegram считается верифицированным — SMS не нужен.
- Никаких секретов на фронте: `BOT_TOKEN` и доступы к Bitrix только на backend.

## 6. Дизайн

- Палитра: `--brand #0AA64B`, `--brand-dark #008A47`, `--brand-light #37C66F`,
  акцент акций `#2FE196`, скидка `#E3262C`. Фон белый, текст `#1A1A1A`.
- Типографика: `Gilroy` (как на сайте) → фолбэк `Manrope` (бесплатный гротеск-аналог) → system.
- Строго фирменный режим: тема Telegram **не** перекрашивает фон/текст (берём только хаптику,
  кнопки, безопасные отступы).

## 8. Дорожная карта

- **Готово (этот этап):** backend-скелет с абстракцией источника, демо-данные в стиле kirgu,
  REST-контракт, проверка initData, связка контакта; фронт — навигация по комнатам, блок акций,
  фирменный стиль, api-клиент с фолбэком на локальные моки.
- **Этап 2:** реализовать `BitrixCatalogSource` (REST/фид/БД), полностью перевести фронт на API.
- **Этап 3:** онлайн-оплата (Telegram Payments / ЮKassa) за абстракцией `PaymentProvider`,
  бонусная программа, история заказов из Bitrix, пуш-уведомления о статусе.
